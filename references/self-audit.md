# 自查清单（交付前必做）

原则：没有本轮的新鲜证据，就不得说「好了」「整齐」「通过」。

## A. 自动检查
```bash
python3 "$SKILL_ROOT/scripts/pdf_audit.py" 报告.pdf [本报告禁用词…]
```
检查文字靠边或越界、末行只剩 1–3 字的孤行、占位符（未取得、…、TODO 等）和禁用词的计数，以及页边墨迹。脚本不查文字重叠（Chrome 的 Type3 字框不可靠），重叠要靠看图。报告专用的禁用词（如已弃用的旧称）作为参数传入，不写进脚本。如果已知某几条遗留警告可以接受，要在交付说明里逐条列出。

## B. 图表数据校验
- 图由脚本从原始序列生成，并输出「图用数据」。
- 零线基线要对，正负柱和符号一致，柱数和点数等于数据行数。
- 高低点、转正点、补回点的年份和数值取自数据。
- 各案例页的坐标范围、字号、图例位置一致；标注不遮挡曲线，也不出图框。
- 横轴时点的口径写明（年末、财年、基期＝100）。

## C. 逐页看图
用 `pdftoppm` 以 100–150 dpi 逐页放大看，不能只看缩略图。检查：卡片等宽等高、栏目对齐、页脚不压内容、表格行高均匀、网址不溢出、无孤行、页眉页脚名称正确、页码引用和实际页一致。逐页打勾；有一处不整齐就改、重导，再从头看。

## D. 颜色与符号清单
- 全文搜红、绿、黄的 CSS 类和内联色，逐条判断是评价还是强调。列清单：页｜文字｜颜色｜判断｜改法。
- 全文搜 ▲▼→，逐处判断是幅度还是水平值，检查颜色、同字重，以及三角后的数字是否同色。

## E. 文字扫描
- 外文文字原样写法（读者不认的文字）计数为 0。
- 版本痕迹词计数为 0（统计含义的「新增」除外）。
- 「见第 N 页」类指向只用于附件，并且不代替关键事实。
- 报告专用的禁用词计数为 0。

## F. 一致性
币别、口径、颜色、术语和基线标签全篇一致；每个数字都能在底表或来源附件里找到；改过的数字，所有引用页一起更新；编号连续，没有悬空引用；PDF 的 sha256 与执行者报告的一致；页数正确。
