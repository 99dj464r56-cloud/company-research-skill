# 公司课题研究（模板，由《美日台大陆个贷负增长历史阶段的影响及应对借鉴》35 轮修改倒推而成）

目标：用户只给一个标题，我一次做到「不用他再挑毛病」的成品。顺序固定：**先立故事（第一页的灵魂），再做内容（排版、取数、验证），最后自查和复核。** 不要一上来就写正文或画图。

## 第一步：故事大纲（先做，先给用户确认）
用一页纸回答六个问题，这就是第一页的设计；答不出来的，后面不得动工。
1. **结论**：一句话，读者看完只记住什么（例：三个市场个贷余额各跌了多少、靠什么走出来）。
2. **研究什么**：对象、口径、期间、范围（哪个余额、哪几个主体、从何时到何时）。
3. **解答什么**：读者心里的那个问题（例：别人收缩时发生了什么、做了什么、哪些有用）。
4. **追求什么**：这份报告要读者做出什么判断或动作。
5. **关键是什么**：决定结论的 2～3 个因果或转折点（为什么进入、为什么走出）。
6. **价值在哪里**：读者拿它能做什么（借鉴、避免、自查），以及它不做什么（不评有效性、不预测）。
大纲同时定：读者是谁、几个部分、每部分一页还是几页、哪些内容进正文、哪些进附件。给用户一页大纲，等确认后再进第二步。

## 第二步：固定的页面架构（倒推出的模板）
- **第 1 页 = 自足的完整摘要**：标题；各对象的大红数字（负增长幅度）加「对象、期间」；「影响」与「应对措施」同一风格逐对象一两行；只放一个小字号的「当前位置」对照卡（本方/本国，约 80% 宽，只作对照、不评有效性、不预测），不在「影响」里写本方；不重复后面的「走入/走出」，不写「见第 X 页」。下半页的影响/应对放大，占页面一半以上。
- **第一部分「发生了什么事」**：每个对象一页：上=走入／走出两个框（为什么进入、关键；为什么走出、关键，白话易懂，约半页）；中=口径说明一行；下=图（半页以内，两条趋势：总量与细分，自己画，不用截图）。**不写借鉴**。
- **第二部分「影响、对策与借鉴」**：每个对象一节（内容确实放不下才用两页）：影响（对哪类机构）、对策按主体拆（监管/政府、银行、企业），每条有案例、是否见效、判断标签，判断必须落在可观察结果并有来源。末节「借鉴汇总」1～2 页：按「值得借鉴／避免踩坑／自查要点」分类（不按国别），类内按监管、银行、消金等主体拆，每条标对象标签和页码。**借鉴只出现在这一节**。
- 「主汇报」＝第一部分＋第二部分；第一部分本身不叫主汇报。页眉页脚统一用这些名字；首页页脚写页码地图。
- **第三部分 附件**（顺序固定）：时间线 → 计算说明（与时间线相连）→ 总体逐年数据与分对象数据（紧邻成对）→ 口径底表 → 口径与名称对照 → 来源与口径登记 → 个案与措施来源。改顺序必须同步改编号、正文引用、页脚与页码引用。长序列（人数、余额、人均）放附件，正文只写一句。
- 版式：A3 横版，白底可打印，空白少，全文约 17～19 页；标题简洁，不写「董事会版」，不留版本痕迹，文件名带日期、只保留一份 PDF。

## 第三步：写作与数字规则（每页都查）
- 读者是决策者：用比例、前后对比、离高点多远、几年恢复；孤立的大额绝对数没有意义。必须保留的重大金额要写，并跟「约合人民币 X 亿元」（取事件年的官方年均汇率，仅作量级参考，汇率与来源写进附件）。
- **币别永远明写**；人均、比率必须写清「谁的、什么的平均」；余额与新增分开标注；统计断点要注明；不用先后顺序推因果（用「不能归因于单一措施」）。
- **减法原则**：每个事实只在最合适的一处写一次，别处用指引；不为凑页数写字；不重复强调「未取得」，能查到的先查（官方/公司来源），查不到的只在页脚一句话中性说明，结果类数字查不到就不写。
- 用最新数据，不停在旧截止日；序列更新后，所有引用页的百分比一起改。
- 全文口径一致：本方与对照对象用同一口径、同一来源体系。
- 颜色固定：好/存续/值得借鉴＝绿 #1E8E4E，预警/并入/自查要点＝黄 #9A6700，坏/退出/避免踩坑＝红 #C62828，结果不明＝灰；标签、图例、图、表全篇一致。
- 白话、短句、不写学术或过程用语；用户列过的禁用词（共 14 个，清单待用户补）出现次数为 0；不得出现「未取得」；无「…」截断。
- 来源：央行、监管、公司公告、行业协会等一手资料优先，序列写代码（FRED 等）；二手数字标「转引」，由我判断是否保留；来源页给完整网址的纯文本（不做可点击超链接）、检索日期范围、逐行核验状态。每个数字都能追到一手来源，追不到的不写。

## 第四步：做法
1. 建待办；重活交给同一个执行者，在用户的 Mac 上做 HTML→PDF（无头 Chrome），每轮用 resume 接着做；每轮前做备份（备份/第N轮前-日期）。成品 PDF 与 HTML 放 /workspace/uploads 与 Mac ~/Downloads。
2. 研究：先搜一手来源，查清每个对象的进入原因、走出原因、措施、案例、结果；每个标题数字都用原始序列重算，公式写进计算说明。
3. 画图：基线在零、柱与数据一致、无遮挡；每个对象两条趋势；图例写清口径（如「2006 年 3 月末＝100」）。
4. **自查（交付前必做，不等用户发现）**：按下面「自查清单」A–D 全部做完；要点：逐页看图——图的基线与柱、文字溢出（尤其附件的网址页）、孤行、页眉页脚名称、页码引用与实际页一致、颜色、币别、重复；核对 PDF 的 sha256 与执行者报告一致、页数、`未取得`与`…`及禁用词的计数。
5. **独立复核**：把最新版与完整要求清单交给用户指定的最高档 Codex（只读），要优先级清单，不改稿；给用户看，按用户批准的改，用户的取舍优先；改完再核。
6. **交付**：只发一份新 PDF，加简短白话改动说明，并如实说哪些没有独立核实。

## 自查清单（交付前必做；目标：图与版面整齐，不让用户发现）
**A. 自动检查**：运行下面脚本（保存为 /workspace/tools/pdf_audit.py；用法 `python3 pdf_audit.py 报告.pdf [禁用词…]`），它查：文字靠边或越界、末行只剩 1～3 个字的孤行（正文必须修；表格单元格里的短行可忽略）、`未取得`／`…`／禁用词计数、四周页边是否有墨迹。它不查文字重叠（Chrome 导出的字体框不可靠），重叠靠看图。每一页的孤行，改法是改写句子，不是缩字号。

```python
#!/usr/bin/env python3
import sys, re, subprocess
import xml.etree.ElementTree as ET
pdf=sys.argv[1]; banned=sys.argv[2:]
out=subprocess.run(["pdftotext","-bbox-layout",pdf,"-"],capture_output=True,text=True).stdout
out=re.sub(r'<!DOCTYPE[^>]*>','',out); out=re.sub(r'xmlns="[^"]*"','',out)
root=ET.fromstring(out); issues=0
for pn,page in enumerate(root.iter('page'),1):
    W=float(page.get('width')); H=float(page.get('height'))
    for w in page.iter('word'):
        x0,y0,x1,y1=[float(w.get(k)) for k in('xMin','yMin','xMax','yMax')]
        if x0<12 or y0<8 or x1>W-12 or y1>H-4: print(f"p{pn}: near edge {w.text!r}"); issues+=1
    for blk in page.iter('block'):
        lines=[''.join((x.text or '') for x in l.iter('word')) for l in blk.iter('line')]
        if len(lines)>=2 and len(lines[-1])<=3 and not re.fullmatch(r'[\d\W]*',lines[-1]):
            print(f"p{pn}: orphan {lines[-1]!r} after {lines[-2][-12:]!r}"); issues+=1
txt=subprocess.run(["pdftotext","-layout",pdf,"-"],capture_output=True,text=True).stdout
for s in ["未取得","…","TODO","NaN","undefined"]+banned:
    if txt.count(s): print(f"string {s!r}: {txt.count(s)}"); issues+=1
print("pages:",len(list(root.iter('page'))),"issues:",issues)
```

**B. 图表数据校验（不靠眼睛）**：每张图由脚本从原始序列生成，同时输出一份「图用数据」；检查：①零线基线位置正确，正负柱方向与数据符号一致；②柱数、点数等于数据行数；③标注的高点、低点、转正点的年份和数值取自数据而不是手写；④两个图的坐标范围、字号、图例位置在所有国别页一致；⑤标注框不遮住曲线、柱或另一个标注，不出图框；⑥图例颜色与全篇颜色规则一致（绿＝净增只表示数量方向时，要注明不是评价好坏）；⑦横轴时点口径一致（年末、3 月末要写明，基线标签如「2006 年 3 月末＝100」）。

**C. 版面逐页看图**（用 pdftoppm 100～150 dpi 逐页看，不要只看缩略图）：同类页的卡片等宽等高、左右栏顶部和底部对齐、图的左右边距对齐、上文下图的比例（文字约半页、图半页以内）、页脚不压内容、表格行高均匀、附件网址不溢出或撞列、孤行与寡行、页眉页脚名称、页码引用与实际页一致。看完每一页后在清单里逐页打勾，有一处不整齐就改完重新生成，再从头看一遍。

**D. 一致性**：币别、口径、颜色、术语、基线标签全篇一致；每个数字能在底表或来源页找到；改过的数字，所有引用它的页一并更新。

## Codex 复核里值得固化的通用做法
1. **按用户的要求清单逐条判定**（通过／部分通过／不通过，附页码和原文引用），而不是泛泛点评。
2. **核心数字全部独立复算**，列表给出算式与结果；复算通过的也要说。
3. **先看第一页能否 30 秒内读懂**：三个核心认识、读者能否一眼带走；结论放最前，不要把总结压在页底。
4. **判断要对应具体目标**：不要写笼统的「有效」，写「有效（补资目标）」；信贷规模恢复与措施目标分开判；做法的结果不明就标不明，不凭先后顺序推因果。
5. **区分终点**：新增转正与余额补回是两个终点；总量增长不等于各细分都增长；「未回到峰值」不等于「没有回升」。
6. **同期口径**：不同期间的数据不能拼成「同期」；总体与细分、本方与对照期间不同要分别注明。
7. **来源闭环**：每条来源给完整网址、发布日期、对应的原文；二手转引标「转引」；序列写准确代码（如 TOTLLNSA 而非 TOTLL）；公告类先找公司或监管原文；用来的监管函要核对函的日期。
8. **时效**：「仍在上市」「已全部返还」这类状态语句必须用最新公告核对。
9. **重复检查**：同一数字在摘要、正文、附件出现时，只保留一处完整表述，其余改指引；同页上下也不重复。
10. **标签与颜色一致**：页眉名称、图例、状态色与评价无关的标签要注明含义。
11. **审稿只读**：复核者不改文件，给「原文→建议文」，由我筛选、给用户看，用户取舍优先；采纳后再核一遍。
12. **术语白话**：摘要里不放行内术语（如「事业再生 ADR」写成「庭外债务重组」），首次出现的机制（如 TALF）用一句话讲清。

## 倒推得到的踩坑清单（先避开）
图基线/柱与数据不符；加网址后附件页溢出；页脚过长；数据截止日过旧；各国口径不一致；规则的日期张冠李戴（要核对监管函本身）；统计断点没注明就说「补回」；人均数字没写主体；金额没写币别；本方情况混进「影响」；第一页、第二部分与第一部分重复；颜色前后不一。
